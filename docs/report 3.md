# board-game-design Agent Skill 深度分析报告与改进执行计划

## 一、整体评估与核心结论

该技能包是目前公开可见的、完成度最高的桌游设计类 Agent Skill 之一，核心优势在于**机制体系专业、全流程闭环、严格遵循渐进式披露原则**，已具备生产级使用价值。

其当前定位是「机制驱动的桌游原型生产工具」，核心短板集中在三个维度：

1. **路由效率仍有冗余**：入口文件未扁平化核心索引，Agent 定位资源存在多余跳转
2. **内容维度有缺失**：强机制、弱体验，缺少主题设计与玩家体验方法论
3. **交付确定性不足**：模板仅有骨架无参照，输出质量依赖 Agent 自身能力

本次改进将围绕「提效、补全、控质」三个核心目标，将其从「优秀的机制工具」升级为「完整的桌游设计生产系统」。

------

## 二、专项深度分析

### 2.1 架构与路由效率：渐进式披露的最后一公里

#### 现状与根因

当前技能包已经践行了「加载最小必要文件」的原则，但路由链路仍存在一次多余跳转：

- **当前路径（3跳）**：用户需求 → `SKILL.md`（总览） → `cheatsheet.md` / `patterns.md`（匹配关键词） → 对应章节（详情）
- 根因：`SKILL.md` 作为唯一入口，没有内置「机制编码-章节」的直接映射，Agent 必须先读取 cheatsheet 才能定位到具体章节文件，窄问题也多了一次文件加载。

此外，缺少**多需求冲突的优先级规则**。当用户同时提出「设计机制+做原型+调平衡」的混合需求时，Agent 没有明确的执行顺序依据，可能出现并行加载多个文件、上下文混乱的问题。

#### 改进价值

- 单机制类窄问题的 token 消耗降低 30%~40%，响应速度显著提升
- 减少路由错误（如找错章节、加载无关内容），提升回答精准度
- 混合需求下执行逻辑更清晰，避免 Agent 无序加载文件

------

### 2.2 内容体系：机制驱动的长板与体验设计的短板

#### 现状与根因

整个内容体系深度锚定《Building Blocks of Tabletop Game Design》，机制分类、编码、权衡分析都非常扎实，但天然存在「机制优先」的偏向：

- 缺失**玩家体验目标（MDA 框架）**的前置约束，设计流程容易陷入「为机制而机制」
- 缺失**主题-机制适配方法论**，无法解决「主题和机制两张皮」的行业普遍痛点
- 缺失**叙事与情绪曲线设计**，对侧重沉浸感的游戏（如美式剧情、合作类）支持不足

根因在于核心参考资料本身就是机制分析著作，未纳入主题设计、体验设计的经典方法论体系。

#### 改进价值

- 覆盖从「主题概念」到「机制落地」的完整设计链路，适用场景扩大 40% 以上
- 从「机制生成器」升级为「完整游戏设计助手」，拉开与普通机制百科的差距
- 补齐独立设计师最刚需的能力：如何让机制服务于体验，而非反过来

------

### 2.3 工程交付：从「有模板」到「好用的模板」

#### 现状与根因

`templates/` 目录提供了全流程的文件骨架，这是很大的亮点，但目前属于「结构型模板」：

- 只有字段标题，无示例填充，Agent 输出时粒度过分自由，格式、详略度不稳定
- 缺少数值平衡类的计算型模板，经济平衡、卡牌数值仍需 Agent 从零搭建
- 没有统一的输出质量自检规则，容易出现规则书缺项、组件表遗漏规格等问题
- 缺少版本号与变更日志，迭代透明度不足

根因是当前阶段优先完成了框架搭建，尚未进入「交付标准化」的打磨阶段。

#### 改进价值

- 输出文件格式一致性提升 60% 以上，大幅降低人工调整成本
- 示例游戏同时起到「演示案例+测试用例」的双重作用，可验证全流程输出能力
- 自检规则将常见疏漏拦截在输出前，提升原型可用性

------

## 三、分级可执行改进计划

按「价值/成本」比分为三级，P0 优先落地，P1 中期补全，P2 长期迭代。

### 3.1 P0 高优先级：基础体验优化（1-2天落地）

#### 任务1：SKILL.md 新增机制编码-章节速查表

- **对应问题**：路由链路冗余，窄问题加载效率低
- **改动文件**：`SKILL.md`
- **执行动作**：
  1. 在入口处新增「Chapter Code Index」表格，列出 13 个章节的编码区间、核心类别、文件相对路径
  2. 补充路由规则：单一机制类问题直接从速查表跳转对应章节，无需加载 cheatsheet；复杂/模糊问题再走 cheatsheet 诊断
- **验收标准**：用户提问「工人放置有哪些核心变体」，Agent 可直接从 SKILL.md 定位到对应章节，无需二次查找其他文件

#### 任务2：新增版本管理体系

- **对应问题**：迭代无记录，用户无法感知更新
- **改动文件**：`SKILL.md`、新增 `CHANGELOG.md`
- **执行动作**：
  1. `SKILL.md` 头部 YAML 新增 `version: 1.0.0` 字段，遵循语义化版本规范
  2. 根目录新增 `CHANGELOG.md`，按「Added/Changed/Fixed」分类记录每个版本的变更
- **验收标准**：每次迭代都有可追溯的版本记录，用户可快速知晓新增能力

#### 任务3：cheatsheet 补充多需求优先级规则

- **对应问题**：混合需求下执行顺序混乱
- **改动文件**：`cheatsheet.md`
- **执行动作**：
  1. 新增「需求冲突决策树」：平衡性诊断 > 机制设计/迭代 > 原型制作 > 主题包装
  2. 说明原则：先解决核心玩法骨架问题，再做交付与包装
- **验收标准**：遇到「帮我设计卡牌游戏并做 PnP 原型还调一下平衡」的混合需求，Agent 按「平衡规则→机制骨架→原型输出」的顺序执行

------

### 3.2 P1 中优先级：核心能力补全（1周落地）

#### 任务1：新增主题与体验设计章节

- **对应问题**：体验设计维度缺失，机制与主题脱节
- **改动文件**：新增 `chapters/ch14-theme-and-experience.md`，同步更新 `workflow.md`、`templates/concept-brief.md`
- **执行动作**：
  1. 第14章核心内容：
     - 基础框架：MDA 模型（机制→动态→体验），明确「体验目标先行」原则
     - 主题-机制适配矩阵：覆盖探险、奇幻、科幻、经济、历史、恐怖 6 类常见主题，列出适配机制与雷区
     - 玩家情绪曲线设计：开局钩子、中期节奏起伏、终局高潮的设计方法
     - 低成本叙事植入：风味文本、事件卡、场景化目标、隐藏信息的用法
  2. `workflow.md` Stage 0（概念阶段）新增「核心体验声明」必填项
  3. 概念简报模板增加「核心体验、目标玩家、情绪曲线」三个字段
- **验收标准**：用户提出「做一个克苏鲁主题的合作推理游戏」，Agent 先输出体验目标与情绪曲线，再匹配对应机制，而非直接堆砌机制

#### 任务2：新增最小示例游戏，作为模板参照

- **对应问题**：模板只有骨架，输出格式不稳定
- **改动文件**：新增 `templates/examples/micro-scavenger/` 目录
- **执行动作**：
  1. 制作一个 2 人、10 分钟的微型卡牌游戏《拾荒者》，完整输出全套文件：
     - `concept-brief.md`、`mechanism-skeleton.md`、`rulebook.md`
     - `components-sheet.md`、`pnp-checklist.md`
  2. 要求机制极简、体量极小，覆盖所有模板字段，仅作格式与粒度参照
  3. 在 `SKILL.md` 中说明：输出文件格式参照 example 目录下的示例
- **验收标准**：Agent 生成的项目文件结构、字段详略、排版规范与示例一致，无格式混乱或字段遗漏

#### 任务3：新增数值平衡计算模板

- **对应问题**：平衡分析缺少结构化工具
- **改动文件**：新增 `templates/balance-spreadsheet.md`，同步更新 `probability-and-balance.md`
- **执行动作**：
  1. 模板包含核心模块：
     - 资源转化率基准表（行动→资源的兑换比例）
     - 卡牌费用曲线模板（费用与战力/效果的对应关系）
     - 雪球效应监控指标（领先玩家优势增长率）
     - 常见概率速算公式（骰子、抽牌、轮次期望）
  2. 在概率平衡文档中增加模板使用说明与基准值参考
- **验收标准**：处理经济平衡或卡牌数值问题时，Agent 可直接基于模板填充参数，无需从零搭建表格

------

### 3.3 P2 低优先级：长期体验打磨（按需迭代）

#### 任务1：新增输出质量自检清单

- **改动文件**：`cheatsheet.md`
- **内容**：规则书、组件表、PnP 文件的必查项，Agent 输出前自动校验，缺项自动补全
- **收益**：将常见疏漏拦截在输出前，原型可用性大幅提升

#### 任务2：扩充失败模式诊断库

- **改动文件**：`probability-and-balance.md`
- **内容**：新增「症状-病因-解决方案」对照表，覆盖雪球效应、后期无聊、先手优势、随机度过大等 10 类常见问题
- **收益**：平衡性诊断更快更准，解决方案更结构化

#### 任务3：补充数字原型导出规范

- **改动文件**：新增 `digital-prototyping.md`
- **内容**：从纸制 PnP 到 Tabletop Simulator / Tabletopia 的转换步骤与规格要求
- **收益**：延伸交付链路，覆盖数字测试场景

## 四、落地路线图与预期收益

| 阶段   | 时间     | 核心任务            | 阶段成果                       |
| ------ | -------- | ------------------- | ------------------------------ |
| 阶段一 | 第1-2天  | P0 全部任务         | 路由效率提升，基础工程规范完善 |
| 阶段二 | 第3-7天  | P1 任务1+任务2      | 体验设计能力补全，输出标准统一 |
| 阶段三 | 第8-10天 | P1 任务3 + P2 任务1 | 平衡工具化，输出质量自检闭环   |
| 阶段四 | 后续迭代 | P2 剩余任务         | 能力边界延伸，持续打磨细节     |

**整体预期收益**：

- 窄问题响应速度提升 30%+，token 消耗显著降低
- 适用场景从「纯机制设计」扩展到「全品类桌游设计」
- 输出文件一致性与可用性大幅提升，用户拿到即可直接打印测试
- 工程规范完善，具备持续迭代的可维护性
